# The Pattern Is The Principle, The Implementation Is The Choice

This system is **not a permissions system**. It does not say "you must use a calendar for date selection". That is an implementation. Teams should feel free to find better implementations of these patterns as long as the underlying pattern is intact.

## What stays consistent vs what can differ

| Always consistent | Can differ intentionally |
|---|---|
| One question per screen | Number of steps |
| Selection auto-advances (for single-answer steps) | Input type used (calendar, grid, cards) |
| Question text is conversational | What the question asks |
| Context strips on dependent steps | What prior answer is shown |
| Helper text on non-obvious questions | Length and tone of explanation |
| Summary before results CTA | What appears in the summary |
| Edit actions on every summary row | How edits are presented |

## What should never drift
The **rhythm**:
- Ask, answer, advance.
- Carry context.
- Explain the unusual.
- Summarise before revealing.
- Edit without penalty.

## What can differ
The depth, the visual density, the number of steps, and the type of decision being made.

- Insurance needs more reassurance.
- Parking needs more precision.
- Transfers needs more logistics.

The patterns accommodate all of these.
